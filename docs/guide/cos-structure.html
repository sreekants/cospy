coslaunch  — one COS process: configuration becomes objects, then every service ticks

boot — config becomes objects · BootLoader · Kernel → Faculties → Services

cos.ini
Environment variables and the section list. Selects the location.
manifests yaml
Each section names YAML files that list the modules to load.
BootLoader
Imports a.b.C and takes class C. Then init → start → run levels 0–4.
builders s3db
Read land, sea, sky and vessel rows by type code into /World.
resolvers
legata.yaml loads term resolvers into the Evaluator.
automata ×41
Each rule compiles its .legata file into a decision tree.

every tick — /Services on_timer · 30 ms step · exceptions caught per tick and logged

World · Actors
Each vessel's behaviour moves it. Land and map bounds block the move.
Weather
Wind, current and wave fields acting on vessels.
monitor 0.5 s
Situation and conduct monitors detect encounters and post them to the rules.
evaluate sample
Everything under /Faculty/Regulation: rules walk automata, examiners score.
DataManager 5 s
Flushes fact rows, keyed by case_id, to the working set.
RPCBroker 5556 · 5557
Serves /Services/API/* to cviz, costopic and cosservice.
