# Working on COS

## Source code comments

- Keep comments short: say what a non-obvious line does or why it exists, in one line where possible.
- No explanatory essays, rationale paragraphs, ticket narratives or design history in source files.
  That belongs in bugs/, docs/ or the commit message.
- Docstrings follow the existing style: one-line summary, then Arguments / Returns.
- Match the comment density of the surrounding code.
- This applies to source code only. YAML and other configuration files may carry detailed comments
  explaining their settings.
